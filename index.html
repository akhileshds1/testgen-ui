How it works

  1. Coverage: looks for existing tests and stops if the flow is already covered
  2. Auth: logs in to the environment
  3. DOM inspect you: watch the browser
  4. Write test: a new file, or extends an existing one
  5. Verify you: run it in your IDE

You can message Claude at any time: while it's working (it picks the message up at its next step) or after it's done. It's the same session, so it keeps all the context. Click Finish when you're happy.

Writing a good brief

  • One flow per run
  • Number the steps, matching the boxes on your screenshot
  • Say what to check at the end
  • Name the user or data to use
1. Change Display name (box 1)
2. Click Save (box 2)
Expect: toast "Profile updated" and the new name in the header
Data: default staging user

Results

  • New: a test written from scratch
  • Modified: an existing test extended
  • No changes: probably already covered, so read Claude's note
  • Compiles doesn't mean passes, so always run it
